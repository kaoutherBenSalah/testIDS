# IDS Platform - Class Diagram & Architecture

## 📊 Complete Class Overview

This document explains the class diagram for the IDS Platform, showing all major classes, their responsibilities, and how they interact.

---

## 🎯 Class Organization by Layer

### **Layer 1: Data Models (models.py)**
Models represent persistent data structures and business entities.

#### **User**
- **Purpose**: Authentication and role-based access control
- **Attributes**:
  - `username`: Unique login identifier
  - `password_hash`: Bcrypt-hashed password
  - `role`: Either "ATTACKER" or "DEFENDER"
  - `created_at`: Account creation timestamp
- **Key Methods**:
  - `verify_password()`: Validate login credentials
  - `get_role()`: Return user's role for access control

#### **AttackRecord**
- **Purpose**: Log and track individual attacks
- **Attributes**:
  - `attack_id`: Unique UUID for each attack
  - `attack_type`: "ARP" or "SYN" 
  - `target_ip`, `source_ip`: Attack endpoints
  - `status`: "ACTIVE" or "COMPLETED"
  - `timestamp`: When attack started
- **Key Methods**:
  - `log_event()`: Record attack progress
  - `get_stats()`: Return attack metrics (packets sent, etc.)

#### **IDSAlert**
- **Purpose**: Represent security alerts generated by detection engine
- **Attributes**:
  - `alert_type`: "ARP_SPOOF", "SYN_FLOOD", or "PORT_SCAN"
  - `severity`: "LOW", "MEDIUM", or "HIGH"
  - `src_ip`, `dst_ip`: Packet source/destination
  - `attacker_ip`: **Local attacker machine IP** (via port scan history)
  - `details`: JSON dict with attack-specific data
  - `acknowledged`: Whether defender reviewed it
- **Key Methods**:
  - `ack()`: Mark as reviewed
  - `block_source()`: Add to firewall blocklist
  - `to_dict()`: Serialize to JSON for UI

#### **NetworkNode**
- **Purpose**: Represent discovered hosts on network
- **Attributes**:
  - `ip`, `mac`, `hostname`: Network identifiers
  - `ports`: Open/scanned ports
  - `is_blocked`: Firewall status
  - `last_seen`: Last activity timestamp
- **Key Methods**:
  - `is_active()`: Check if host is responsive
  - `get_open_ports()`: Return discovered services
  - `mark_blocked()`: Update firewall state

### **Layer 2: Attack Modules (modules/)**
Modules that implement actual attacks and reconnaissance.

#### **ARPSpoofer** (arp_spoof.py)
- **Purpose**: Launch ARP spoofing (Man-in-the-Middle) attacks
- **Attack Mechanism**:
  - Sends crafted ARP replies claiming to be the gateway
  - Redirects traffic from victim through attacker
  - Enables packet interception and modification
- **Attributes**:
  - `interface`: Network adapter (e.g., "eth0")
  - `target_ip`: Victim to redirect
  - `gateway_ip`: Legitimate gateway being spoofed
  - `interval`: Time between ARP packets (2 seconds)
  - `is_running`: Flag to control spoof loop
  - `packet_count`: Total packets sent
- **Key Methods**:
  - `start_spoof()`: Begin attack in background thread
  - `stop_spoof()`: Gracefully terminate
  - `_send_packets()`: Core ARP packet generation
  - `get_stats()`: Return metrics for dashboard

#### **SYNFlooder** (syn_flood.py)
- **Purpose**: Launch SYN flood (Denial-of-Service) attacks
- **Attack Mechanism**:
  - Sends thousands of SYN packets from spoofed IPs
  - Target exhausts connection resources
  - Legitimate users cannot connect
- **Attributes**:
  - `interface`: Network adapter
  - `target_ip`: DOS victim
  - `target_port`: Service port (80, 443, 22, etc.)
  - `num_threads`: Parallel attackers (usually 10-20)
  - `is_running`: Attack flag
  - `packets_sent`: Cumulative packet count
- **Key Methods**:
  - `start_flood()`: Spawn multiple attack threads
  - `stop_flood()`: Terminate all threads
  - `_flood_thread()`: One attacker sending spoofed packets
  - `get_packet_count()`: Return total SYNs sent

#### **NetworkScanner** (network_scanner.py)
- **Purpose**: Passive and active network reconnaissance
- **Scanning Types**:
  - **Ping sweep**: Identify active hosts
  - **Port scanning**: Detect open services
  - **OS fingerprinting**: Guess operating system
  - **Hostname resolution**: Reverse DNS lookups
- **Attributes**:
  - `interface`: Network adapter
  - `timeout`: Response wait time
  - `stop_requested`: Signal to cancel scan
- **Key Methods**:
  - `scan_subnet()`: Ping sweep to find hosts
  - `identify_active_machines()`: Full discovery with port scan
  - `_resolve_hostname()`: Reverse DNS for IPs
  - `scan_ports()`: Port enumeration on single host
  - `stop_scan()`: Graceful cancellation

#### **TrafficSniffer** (traffic_sniffer.py)
- **Purpose**: Capture and analyze network packets
- **Capabilities**:
  - Filter by BPF (Berkeley Packet Filter)
  - Capture in real-time or to PCAP file
  - Callback-based packet processing
- **Attributes**:
  - `interface`: Network adapter
  - `filter_string`: BPF expression (e.g., "tcp port 80")
  - `is_sniffing`: Capture flag
  - `captured_packets`: In-memory packet list
  - `packet_count`: Total captured
- **Key Methods**:
  - `start_sniffing()`: Begin capture in background thread
  - `stop_sniffing()`: End capture
  - `_sniff_thread()`: Core Scapy packet capture
  - `get_packets()`: Retrieve captured data
  - `enable_pcap_logging()`: Write to file for analysis

### **Layer 3: Defense Modules (modules/)**
Modules for detecting attacks and blocking threats.

#### **IDSMonitor** (ids_monitor.py) - **⭐ CORE ENGINE**
- **Purpose**: Continuous network monitoring and threat detection
- **Detection Thresholds**:
  - **ARP Spoof**: MAC address changes from same IP
  - **SYN Flood**: 150+ packets from 15+ sources in 10s window
  - **Port Scan**: 10+ unique ports probed in 10s window
- **Attributes**:
  - `interface`: Monitored adapter
  - `network_range`: CIDR network to monitor (e.g., "192.168.1.0/24")
  - `is_running`: Monitor flag
  - `stats`: Detection counters {arp_events, syn_events, port_scans}
  - `alerts`: List of IDSAlert objects
  - `port_scan_tracker`: Dict tracking IPs that scanned ports
  - `local_attackers`: Dict of identified attacker machines
- **Key Detection Methods**:
  - `detect_arp_spoof()`: Identifies MAC changes
  - `detect_syn_flood()`: Analyzes SYN packet patterns
  - `detect_port_scan()`: Detects service enumeration
  - `_detect_local_attacker()`: **Correlates attacks with port scan history** to find real attacker IP
- **Key Management Methods**:
  - `start()`: Begin monitoring
  - `stop()`: End monitoring
  - `get_stats()`: Return dashboard metrics
  - `get_alerts()`: Return recent detections
  - `ack_alert()`: Mark alert as reviewed

#### **FirewallBlocker** (firewall_blocker.py)
- **Purpose**: Enforce network blocking via OS firewall
- **Blocking Methods**:
  - **Linux**: iptables rules (DROP traffic from IP)
  - **Windows**: netsh (future implementation)
- **Attributes**:
  - `os_type`: "linux" or "windows"
  - `blocked_ips`: Set of blocked IP addresses
- **Key Methods**:
  - `block_ip()`: Add firewall rule for IP
  - `unblock_ip()`: Remove firewall rule
  - `get_blocked_ips()`: List all blocked IPs
  - `flush_rules()`: Remove all firewall rules
  - `_execute_iptables()`: Execute iptables command

### **Layer 4: Utility Modules (utils/)**
Shared helper functions and logging.

#### **Logger** (logger.py)
- **Purpose**: Centralized logging for all modules
- **Attributes**:
  - `name`: Logger identifier (e.g., "ARPSpoofer", "IDSMonitor")
  - `log_file`: Output file path
  - `level`: Verbosity level
- **Key Methods**:
  - `info()`, `warning()`, `error()`, `debug()`: Log at different levels
  - `write_log()`: Persist to file

#### **NetworkUtils** (network_utils.py)
- **Purpose**: Network configuration and utility functions
- **Static Methods**:
  - `get_local_ip()`: Query local IP address
  - `get_gateway_ip()`: Find default gateway
  - `get_default_interface()`: Get primary network adapter
  - `get_default_network_range()`: Calculate network CIDR
  - `ip_in_range()`: Check if IP in CIDR range
  - `get_mac_address()`: ARP lookup for MAC

### **Layer 5: Flask Application & Routes**

#### **IDS_App**
- **Purpose**: Main Flask application initialization
- **Responsibilities**:
  - User authentication setup
  - Blueprint registration
  - Session management
- **Key Methods**:
  - `initialize()`: Configure Flask
  - `register_blueprints()`: Load route modules
  - `setup_routes()`: Define endpoints
  - `run()`: Start web server

#### **AttackRoutes** (routes/attacks.py)
- **Purpose**: Endpoints for attacker interface
- **Endpoints**:
  - `POST /api/attack/arp/start` → `start_arp_attack()`
  - `POST /api/attack/arp/stop` → `stop_arp_attack()`
  - `POST /api/attack/syn/start` → `start_syn_attack()`
  - `POST /api/attack/syn/stop` → `stop_syn_attack()`
  - `GET /api/attack/stats` → `get_attack_stats()`
- **Access Control**: Requires `user_role == 'ATTACKER'`

#### **IDSRoutes** (routes/ids.py)
- **Purpose**: Endpoints for defender interface
- **Endpoints**:
  - `POST /api/ids/start` → `start_ids()`
  - `POST /api/ids/stop` → `stop_ids()`
  - `GET /api/ids/status` → `get_ids_status()`
  - `POST /api/ids/discover` → `discover_nodes()`
  - `GET /api/ids/overview` → `get_overview()`
  - `GET /api/ids/alerts` → `view_alerts()`
  - `POST /api/ids/alerts/<id>/ack` → `ack_alert()`
  - `POST /api/ids/block` → `block_ip()`
- **Access Control**: Requires `user_role == 'DEFENDER'`

#### **APIRoutes** (routes/api.py)
- **Purpose**: Utility endpoints for scanning and sniffing
- **Endpoints**:
  - `POST /api/scan/start` → `start_scan()`
  - `POST /api/scan/stop` → `stop_scan()`
  - `GET /api/scan/results/<id>` → `get_scan_results()`
  - `POST /api/sniff/start` → `start_sniffer()`
  - `POST /api/sniff/stop` → `stop_sniffer()`
  - `GET /api/sniff/packets/<id>` → `get_packets()`
  - `GET /api/network/info` → `get_network_info()`
- **Access Control**: Requires `user_role == 'ATTACKER'`

## 🔗 Relationships Explained

### **Composition** (Arrow `-->`)
"Has-a" relationship - stronger coupling

| From | To | Meaning |
|------|-----|---------|
| ARPSpoofer | AttackRecord | Logs each attack attempt |
| SYNFlooder | AttackRecord | Logs each flood session |
| IDSMonitor | IDSAlert | Creates detection alerts |
| IDSMonitor | FirewallBlocker | Uses blocker to enforce rules |
| Routes | Modules | Instantiate and control modules |

### **Dependency** (Dashed `...>`)
"Uses-a" relationship - looser coupling, typically for utilities

| From | To | Meaning |
|------|-----|---------|
| All Modules | Logger | Call logging functions |
| All Modules | NetworkUtils | Query network info |

### **Association** (Line `--`)
"Knows-about" relationship - modules interact with data models

## 📈 Data Flow Example: Attack Detection & Blocking

```
1. Attacker executes ARPSpoofer.start_spoof()
   ↓
2. ARPSpoofer sends ARP packets, logs to AttackRecord
   ↓
3. NetworkScanner.scan_subnet() detects port scan activity
   ↓
4. IDSMonitor._detect_local_attacker() correlates:
   - Port scan from 192.168.111.20 in history
   - Identifies as LOCAL attacker (not spoofed)
   ↓
5. IDSMonitor.detect_arp_spoof() detects duplicate MAC
   ↓
6. IDSAlert created with:
   - attacker_ip: 192.168.111.20 (real attacker)
   - src_ip: 192.168.111.30 (victim)
   - details: {spoofed_sources: [...], ...}
   ↓
7. Defender views alert in UI
   ↓
8. Defender clicks "Block" button
   ↓
9. IDSRoutes.block_ip(192.168.111.20) called
   ↓
10. FirewallBlocker.block_ip() executes:
    iptables -I INPUT -s 192.168.111.20 -j DROP
    ↓
11. NetworkNode.is_blocked = True
    ↓
12. All traffic from attacker machine is dropped
```

## 🎓 Key Design Patterns

### **Model-View-Controller (MVC)**
- **Models**: User, AttackRecord, IDSAlert, NetworkNode
- **Views**: HTML templates (attacker.html, defender.html)
- **Controllers**: Flask routes (AttackRoutes, IDSRoutes, APIRoutes)

### **Strategy Pattern**
- Different attack implementations (ARP vs SYN)
- Pluggable detection algorithms
- OS-agnostic firewall blocking

### **Observer Pattern**
- IDSMonitor continuously watches for events
- Generates alerts when thresholds exceeded
- Defender UI polls for new alerts

### **Singleton Pattern**
- Single IDSMonitor instance per session
- Single FirewallBlocker instance
- Prevents conflicts and duplicates

## 💾 Database Storage

All classes store data persistently:
- **Users**: `data/users.json`
- **Alerts**: In-memory during session, logged to `logs/`
- **Network Nodes**: Cached in IDSMonitor.nodes_cache
- **Firewall Rules**: Applied directly via iptables
